# AZCine 设计规范

> 更新：2026-10-07。只记当前有效视觉与交互，不放测试流水账。整体方向冻结：亮暗同布局、首页B、公司卡片→自由文档、正常通用聊天；只按阶段补必要状态。

## 1. 体系与共用规则（后续模块必须沿用）

用户2026-10-06明确要求将polish已建立的统一UI组件库作为后续模块设计标准。主题基线为已合main的 `polish/all-part@4affaf8`：ShadcnStore灰阶主题、shadcn/ui与项目业务变体；`polish/dev-2@d7ae820` 已补共享表单弹窗、中文月份和短提示。product_6.0负责流程；其出厂样式和旧 `design/` 原型只作历史参考，不再覆盖生产主题、组件或已选布局。保留现有业务交互，不为统一样式重选方向。

### 规范与源码的职责

| 入口 | 唯一职责 |
|---|---|
| 本规范第1节及对应模块章节 | 有效设计要求、接入规则和允许的业务例外 |
| `app/src/styles/tokens.css` | 亮暗颜色、字体、间距、圆角及壳尺寸的唯一取值来源 |
| `app/src/styles/globals.css` | 唯一生产样式入口；按theme/base/components/utilities层组织，与总览共用 |
| `app/src/components/ui/` | 通用组件及共用控件样式；`controls.css`、`business-controls.css` 与日期/项目菜单/阶段零件 |
| `app/src/ui-preview/`、`app/ui-inventory.ts` | 页面/详情/组件/状态展示及源码清单；只辅助查漏，不代替验证 |

需求决定变了先交接；组件或变量改了在同轮同步受影响规范。新会话先读本节和任务模块，再核对自己Worktree的实际库版本；旧分支缺组件时不得用旧文档或复制样式静默补第二套UI。主目录维护文档真源，功能分支提供摘要。

### 颜色与主题

主题只用根 `data-theme="light|dark"`，由现有 `theme.ts` / `use-theme.ts` 管理；未手动选择跟随系统，手动选择本机保存。Tailwind的dark变体也绑定同一属性，不新增独立 `.dark`、模块主题状态或局部亮暗配色。以下是当前源码值，不是已经量测的对比度结果。

| 语义变量 | 亮色 | 暗色 |
|---|---|---|
| `background` / `foreground` | `oklch(1 0 0)` / `oklch(.145 0 0)` | `oklch(.145 0 0)` / `oklch(.985 0 0)` |
| `card`、`popover` | `oklch(1 0 0)` | `oklch(.205 0 0)` |
| `primary` / `primary-foreground` | `oklch(.205 0 0)` / `oklch(.985 0 0)` | `oklch(.922 0 0)` / `oklch(.205 0 0)` |
| `muted`、`accent` | `oklch(.97 0 0)` | `oklch(.269 0 0)` |
| `muted-foreground` | `oklch(.48 0 0)` | `oklch(.708 0 0)` |
| `border` / `input` | `oklch(.922 0 0)` / 同border | 白10% / 白15% |
| `ring` | `oklch(.708 0 0)` | `oklch(.556 0 0)` |
| `sidebar` | `oklch(.985 0 0)` | `oklch(.205 0 0)` |
| `ok` / `warn` / `bad` | `#15803D` / `#A16207` / `#B91C1C` | `#4ADE80` / `#FACC15` / `#F87171` |

旧业务变量是同一主题的别名：bg→background、island→card、island-2→muted、text→foreground、t2/t3→muted-foreground、ink/acc→primary、line→border、line-2→input。新样式使用语义变量或映射后的Tailwind类，不在模块写新颜色值、覆盖根变量或恢复旧蓝紫强调色。阶段标签的多色身份、Agent已发送黑白气泡和Windows关闭按钮的系统红是具名业务例外；状态色只代表实际状态，不作装饰。轻描边和 `shadow-card` 可用于现有卡片，浮层复用 `shadow-pop`，不叠加自造阴影。

正文对比度目标≥4.5:1，控件和焦点对相邻面目标≥3:1；状态还需文字/形状。交互控件使用组件库现有可见焦点样式，不能用模块 `outline:none` 抹掉；无框编辑控件或其明确对应的容器必须有可见焦点。程序定位到非交互页标题可保持现有无装饰焦点规则。亮暗主题及对比度未重验，不因规范登记标通过。

### 排印、间距与尺寸

| 用途 | 当前默认 |
|---|---|
| 页标题 | `fs-title/lh-title`＝24/32，现有h1字重700 |
| 区/条目标题 | `fs-h/lh-h`＝16/24，字重600 |
| 正文/控件、阅读正文 | 14/22、16/28 |
| 次级/元信息、数字特征 | 13/20、12/18、30/38 mono |
| 间距 | `s-1…s-8`＝4/8/12/16/24/32/48/64 |
| 圆角 | `radius`＝.625rem（默认16px根字体下10px）；island＝12px、panel＝10px、ctl/xs＝6px，pill＝999px |
| 控件 | Button默认36px，sm32px、lg40px、xs24px；Input/NativeSelect默认40px，app变体36px；已有业务紧凑控件按库变体，不全站强行40px |
| 壳/图标 | 顶栏56px、导航展开240px/收起64px、主内容内距24px、通用图标16px |

字体直接用 `--font`（Inter及现有系统回退，中文Microsoft YaHei），等宽用 `--mono`；不引入网络字体。标题可换行、URL可断行，不缩字塞内容。公司编辑名称24/32、文章标题28/38、Agent正文14/23等既有业务层级只用于对应模块。颜色、圆角、一般排印、留白都从变量/组件取；业务阅读宽度和表格列宽可保留模块参数，不把一个页面的局部尺寸扩大成全站默认。

普通交互沿用140ms，主题切换复用现有 `theme-transition.ts` 的400ms圆形展开与降级；减少动态偏好关闭，不自加页面循环动画。当前实现与动态/焦点实际表现仍待授权验证。

### 组件选用与扩展

| 场景 | 应复用的组件/控件 |
|---|---|
| 动作与导航 | `Button`、`UILink`、`ActionGroup`；主动作default、次动作outline/secondary、低强调ghost/link，危险动作destructive |
| 业务按钮 | Button已有 `app-*` 变体；变体定义在 `button.tsx`，皮肤由组件CSS管理，不在页面重造同义按钮 |
| 输入与选项 | `Input`、`Textarea`、`NativeSelect`、`Label`、`Checkbox`、`Switch`；app用于现有业务密度，inline用于已有无框编辑，沿用对应焦点/校验 |
| 容器/反馈 | `Card`、`Badge`/`StatusBadge`、`Alert`/`Feedback`、`EmptyState`、`Skeleton`、`LoadingStatus`、`Progress`、`OperationToast` |
| 折叠/浮层/长表 | `Disclosure`、`Dialog`、`FormDialog`、`Popover`、`DropdownMenu`、`Tooltip`、`Tabs`、`Table`、`Separator` |
| 项目与桌面 | `DateInput`、`MonthInput`、`ProjectStagePicker`、`TableMenu`、`ProjectAddMenu`、`WorkspaceHeader`；不复制日历/标签/窗口控件 |

`feat/agent-dev@62c93dc` 已在同库增加AttachmentPreview、RecordContextMenu、StatusDot、ScaleLoader、MessageMarkdown与AgentSidebar/Entry；FormDialog支持固定footer/宽核对容器，Table支持containerProps传递局部滚动参数。记录右键与文本复制/剪切/粘贴分开，动作绑定真实记录，不覆盖输入区原生编辑语义。新增状态已登记UI总览，未运行验证。

复用真实导出和现有参数，不凭此表猜不存在的API。局部CSS只负责模块布局、内容排版和具名业务尺寸，选择器限定模块容器；不在模块全局改button/input/svg/通用组件皮肤。基础控件不能直接用原生标签另画样式；语义正文、复杂表格单元格/编辑、原生日期与文件能力等确有需要时可保留原生节点，但复用组件库样式/焦点并记录业务原因。新增可复用零件放同一 `components/ui/`，新增变体在既有组件定义，不创建第二组件库、不复制Radix实现、不未经需求扩大依赖。

弹层按用途选组件；保留键盘、Escape、外点关闭及返回触发控件，现有项目top-layer菜单不要替换成会挤行或受裁切的局部面板。列表、详情、设置保持正常路由；新建项目、待办、灵感、信源、记一笔及开销编辑按最新用户决定使用 `FormDialog`，背景保留所属页面。关闭保未提交草稿，保存失败保输入，关闭过渡期间保留表单内容，迟到回执不能关闭后来重新打开的弹窗或覆盖新草稿。

### 操作反馈与生命周期（2026-10-06 用户要求）

所有模块统一遵循：操作完成后的短提示放在顶部栏右侧、窗口控制按钮之前，提示一会自动消失；不得在页面或弹窗中堆积常驻“已保存 / 已删除 / 已复制”等段落。同一个错误也不得同时显示在弹窗及其背后的列表。此规则适用于后续模块。当前通知通过Portal固定于窗口右上，顶部16px，右侧预留132px窗口按钮加16px间距，不参与正文布局或窗口拖动。

- **短暂操作回执**：保存、删除、恢复、复制、导出、取消、获取模型、配置与目录操作的结果使用同库 `OperationToast`。控制器通过 `notifyOperation` 或 `useOperationNotice` / `useOperationNotices` 发布；顶部壳只挂载一个展示实例，页面不重复渲染 notice。只显示最新一条，新操作替换旧提示并重新计时；普通提示 4 秒，有撤销动作 6 秒。悬停或键盘聚焦暂停计时，离开继续；可手动关闭。长文本在固定宽度内省略，悬停可查看全文；不挤正文、不遮挡窗口按钮。取消不报成功。
- **撤销**：最近一次删除或状态修改可将“撤销”动作附在提示内，沿用真实记录及版本核对；不能因提示消失就删掉业务记录或草稿。存在已删除列表时，长期恢复入口留在该列表。文档内部行列、块、清单的编辑撤销属于编辑工具，可以留在对应工具区，不能当作常驻操作成功提示。
- **表单校验**：错误归属对应草稿和字段，放在字段附近；金额、用途等输入通过 `aria-invalid` 与 `aria-describedby` 关联错误。后台保存失败留在当前表单，保留输入；同一草稿的错误不复制到背景列表或其他表单。编辑、重试后更新对应错误，成功后清除。不得把用户仍需修改的错误做成转瞬即逝的提示。
- **处理中与待核对**：等待、任务进度、版本冲突、保存回执不确定、读取失败等必须保留在当前任务 / 表单 / 页面的一处，提供对应处理入口。弹窗承担该状态时，背景页不再重复显示；关闭后仍需处理的请求可由页面接管。已有内容刷新时保留列表和输入，使用 `LoadingStatus` 延迟提示，不在快速保存时插入一行文字造成闪动。
- **长期事实与异常**：记录的报销状态、任务终态、来源限制、覆盖缺口、翻译不完整、未接入能力和真实运行异常属于内容或能力说明，留在所属区域；不冒充一次性操作回执。历史状态以记录呈现，不能重新读取一次就重播旧的成功提示。
- **库与交接**：通知外观、亮暗语义颜色和计时逻辑集中在 `components/ui/operation-toast.tsx` / `.css`，模块只提供文案与动作。UI 总览登记提示、替换、撤销、失败、长文本，以及弹窗字段校验和删除确认的内存示例。登记代码不等于经过 UI 验证。

### 后续模块的接入顺序与交接要求

1. 定位已确认需求及本模块设计章节，列出页面/详情/编辑落点，复用当前壳、路由和控制器边界。
2. 对照组件总览的源码选择现有组件和变体；先复用，缺少的通用零件才在同库局部扩展。长寿命控制器保留草稿，异步回执核对目标/版本，失败保旧数据和输入。
3. 同步 `ui-preview/catalog.ts` 的场景、来源文件与状态；交互补 `state-actions.ts`，数据/控制器补明确的内存fixture，组件补 `components.tsx`，样式仅总览外围可用 `preview.css`。总览必须复用生产组件与globals，不能做一套只给演示看的页面，也不能调真实保存/采集/模型/文件接口。
4. 至少登记正常、首次空/加载、已有内容刷新、失败保留、长文本；有编辑/异步/危险动作时另登记草稿、保存中/失败/冲突、取消与确认。把路由/返回、主题、最小窗口适配、焦点与未完成状态一并交接；新增节点被源码清单发现不等于场景与全部条件自动覆盖。

实现核对项：复用组件/变量、样式作用域、固定容器内部滚动、输入保留、真实反馈、总览覆盖和返回路径。授权UI验证时才在亮暗1440×900/1280×800/1024×768实际启动、操作、截图并亲看；没有授权就仅说明代码登记和静态核对，不运行测试/类型检查/构建/UI验证、不委派、不标验收通过。规则制定不新增Hooks或自动检查关卡。

## 2. 壳、导航与首页B

- 复用 `WorkspaceHeader`：顶部56，导航展开240/收起64，主区与侧栏衔接，主面顶部8px、圆角取r-island，普通内容内距24。今天与项目采用容器内距24，不把内容压成居中窄栏；项目入口、详情均从主容器左侧对齐。真实系统按钮/拖动由桌面负责，HTML不冒充可用系统壳。
- 基准1440×900、常用1280×800、最小1024×768。≤1100首次打开默认收起导航为64（仍可手动展开）、普通内容内距24、今天内距16，项目仍用24；先收辅助区再收留白，不裁按钮或硬缩字。
- 主导航分“工作台”（今天/项目/资讯/模型榜/灵感/记账）和“工具”（Agent/后台任务/规则与资源）两组；设置与主题按钮在底部。规则与资源独立 `#resources`，固定为工具组最后一项，不回放到设置重复入口。当前页 `aria-current`，主题/筛选 `aria-pressed`。
- 共用外壳占窗口可用高度：顶部、左侧导航、模块标题固定，主容器顶底和圆角边界始终在窗口内；正文只在右侧模块内容区内部滚动，不带动整个页面和左侧导航。内容多时左导航可在自身区域滚动，不能与正文联动。页标题/右侧动作共中心线、区标题同基线。此规则供所有现有及后续模块复用。
- 完整AZCine字标用 `assets/brand/logo-lockup.png`，保完整形状，不再拼“AZ方块+文字”；亮色黑字、暗色同形浅字，窄导航等比缩小不裁字。
- **首页只用B·工作双栏**：待核对整行在上，待办/最近交付等宽双栏，资讯整行在下。卡片内距24、间距16；对象直接进入正常详情。未接入模块明确说明，不用演示数据/虚构计数冒充正式内容。
- 待办标题必填，可选完整日期和公司项目；新增表单使用共享弹窗，短标题＋日期/项目辅助行，筛选/列表是主内容，不铺长标签表单占满首屏。保存失败保草稿，完成可单次撤销/恢复，来源可回查。首页交付由指定list派生。
- 项目和待办共用日期输入＋日历图标；浮动月历含明确年月、上/下月、周一至周日与日期网格、今天/清空，可键入完整YYYY-MM-DD。选择/取消不猜年份；方向键日/周、PageUp/Down月份、Home/End周边、Enter选择、Escape返回触发按钮、Tab可离开。弹层在top-layer，不挤行或被横滚裁切，沿用灰面/唯一强调色。
- 今天的短暂操作回执与最近一次状态撤销统一放在顶部栏通知，按第1节自动消失，不常驻在正文。异步操作中保持按钮/输入/列表位置和样式，局部等待状态与aria-disabled保护防连点，不整组褪色，不替换已有列表为加载段落。读取失败保旧数据并明确提示，未接入信息仍不造假。

- **2026-10-07今日资讯**：优先最近日报，按实际文章ID去重取最多10条；无新reader刊期时兼容旧overview/events。显示真实日期/来源及进入文章/事件入口，不凑数；高度 `min(360px, 40dvh)`，列表内部纵向滚动、标题换行且键盘可进入滚动区，不改变整体窗口。

## 3. 公司项目：入口与文档

### 卡片入口

- 项目入口使用主容器全宽，公司/个人两个section；工具栏、区标题、卡片网格与个人待定块统一左对齐，不保留最大1120居中窄栏。
- 公司入口用小尺寸双层卡片：网格最小列宽248、卡片最大320、间距16，随容器宽度自动增加/减少列数；不固定两列或随项目数少拉成大卡。身份区130高/内距16，底部交付区90高，所有状态的色块分界线对齐。
- 顶行文件夹图标＋公司项目/内容块数，标题最多两行、简介一行省略；底部统一为交付状态/完整日期或日期待补或暂无安排/数量与待补信息，右侧小圆角箭头入口。名称、内容标题和交付摘要由正式文档派生，不编数据或重复录入；长文本不撑乱卡片高度。
- 搜索保留列表，“新建公司项目”使用共享 `FormDialog`；旧 `#projects/new` 进入列表并打开创建弹窗，详情仍为正常页。个人模块仅待定块，不加创建/内部假功能。
- 卡片菜单与详情提供删除确认，项目移入“已删除”列表，可恢复或通过短提示撤销；保留文档、关联与未提交草稿，已删除项目退出交付汇总，不做永久清除入口。
- 不恢复旧四页签、旧镜头详情表、部门/团队/本轮修改演示块或素材索引器。

### 文档与交付摘要

- 详情使用主容器全宽，顶部固定返回/面包屑、可改名称、清单展开/收起、保存与添加内容；标题无框，不用长技术说明占首屏，不再设独立阶段标签页头动作或大管理面板。保留搜索/返回与创建弹窗入口；保存短回执遵循第1节，真实保存失败或待核对状态留在所属区域。
